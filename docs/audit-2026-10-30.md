1. **采购附件接口必崩**：`app/portal/api.py:1403` 写了裸名 `SyncError`（模块里只导入别名 `_SyncError`），走"记录不存在"分支就 `NameError` → 500，并顺带丢掉审计记录、留下孤儿附件。

## 3. P1（10 项）

### P1-1 采购附件上传：裸名 `SyncError` → `NameError` → 500 + 孤儿附件

- 位置：`app/portal/api.py:1403`；导入别名 `app/portal/api.py:662`；捕获处 `app/portal/api.py:1454`
- 现象：`raise SyncError("api", "采购记录不存在（或已从源表移除）")` 用的是裸名，而模块 `from .sync import SyncError as _SyncError`——全文件没有 `SyncError` 这个名字。
- 触发：`POST /api/portal/write/procurement/{record_id}/attachments`，且记录已被从飞书删除 → `_procurement_live_fields()` 返回 `None` → `NameError`，外层 `except _SyncError` 捕不到 → FastAPI 500 无 detail（本应是 502"采购记录不存在"）。
- 连带影响：① `_audit("portal_procurement_upload", ...)` 不会执行，审计丢失；② `w.upload_attachment()` 在抛错前**已成功**消耗了 file_token，留下孤儿附件，用户重试会重复上传。
- 证据：`ruff` 的 F821 命中；`grep -n "SyncError" app/portal/api.py` 只出现 `_SyncError` 与这一处裸名。
- 修复：该行改 `raise _SyncError(...)`；同时把 `except _SyncError` 扩为兜底 `except Exception` 再转 502，避免同类拼写错误静默 500。

### P1-2 增量推送不幂等 → 工时重复结算

- 位置：`app/portal/pusher.py:78`、`app/portal/pusher.py:225-243`、`app/portal/cache_rules.py:151-153`、`app/portal/cache_rules.py:225-226`、`app/portal/cache_store.py:573-583`
- 现象：`requeue_stuck(older_than=0)` 在启动时把 `pushing` 一律打回 `pending`；`_update` 每次重试都重新 `client.get` 读飞书当前值，再 `plan.push[col] = apply_increment(remote_fields.get(col), delta, ndigits)`，而 `apply_increment` 是 `round(to_number(current) + float(delta), ndigits)`——**完全不看入队时的 base**。
- 触发：09:00 签到、17:00 签退，飞书当前 22.0 → 写 30.0 实际成功但 HTTP 超时 / 进程在 `complete_update` 前被杀 → 重启后重推，读到 30.0 再 +8 → 38.0。
- 影响：工时翻倍，且 `attendance_sessions.hours` 仍是 8（明细对、汇总错），事后对账发现不了。
- 修复：增量写加 CAS——入队时持久化 expect 值，推送前比对，不符则不推增量、改为按明细重算绝对值或记 `conflict`。更彻底的做法是取消增量语义，一律写"周初时长 + Σ本周已结算会话"的绝对值（幂等）。

### P1-3 直写签退把快照当累计基数 → 短窗口两次会话覆盖丢工时

- 位置：`app/portal/api.py:2005`（上下文 2001-2009）
- 现象：`total = round((m.get("work_hours") or 0) + session_h, 2)`，`m` 来自 `store.current()` 快照。
- 触发：快照 10.0 → 09:00 签到 / 09:31 签退写 10.52 → 09:33 再签 / 10:35 签退时 `m` 仍是 10.0（快照未刷新）→ 写 11.03，真实应为 11.55，第一次 0.52h 被覆盖。`_ATTEND_LIVE` 只挡非法状态，不校正基数。
- 修复：基数取 `cache_store.get_remote("members", rid)` 的镜像当前值并断言 ≥ 快照值；或直写路径统一改走队列增量写。

### P1-4 换周"周初时长"取自快照 → 上周工时渗入本周

- 位置：`app/portal/api.py:2014-2019`，配合 `app/portal/attendance.py:117`
- 触发：上周五快照 12.0，周末实际加了 3h 未同步；周一 09:00 签退 +2h 触发兜底换周 → 周初时长写 12.0 → 飞书公式"本周时长" = 17 − 12 = 5.0，真实 2.0，多出的 3h 记进本周，`attendance.py:182` 的 `week_ok` 由未达标翻成达标。
- 修复：同 P1-3 取镜像值；换周后自检 `0 <= 本周时长 <= 本周已结算会话之和`。

### P1-5 表单控件没有可访问名称（读屏只会念"编辑框 空白"）

- 位置：`web/src/portal/components/WriteForm.vue:152-171`
- 现象：字段名是 `<span class="form-label">`，控件只有 `:data-k`，没有 `id`/`for`/`aria-label`/`aria-labelledby`。事项表单 9 个字段、采购表单 16 个字段全部如此；同文件 167-171 行的 `radio`/`checks` 反而规范地用了 `<label>`。
- 影响：读屏无法得知字段含义，鼠标点标签也不会聚焦对应控件。
- 修复：`<span>` 改 `<label :for="'f-' + r.k">`，控件加 `:id="'f-' + r.k"`；不改结构则给 span 加 id 并用 `aria-labelledby`。

### P1-6 人员选择器"移除"是 span 冒充按钮，键盘不可达且非法嵌套

- 位置：`web/src/portal/components/PeoplePicker.vue:96-111`（移除控件在 109 行）
- 现象：`<span class="people-tag-x" role="button" aria-label="移除">×</span>` 无 `tabindex`、无 `keydown`，而且嵌在外层 `<button>` 内部（HTML 规范禁止 button 内嵌交互内容）。
- 影响：键盘用户选错负责人后无法单独移除，只能清空重选；部分浏览器点击目标归属不一致，可能点 × 反而展开面板。
- 修复：已选标签容器移出 `<button>`，× 换成真 `<button type="button">`；支持 Backspace 删末位。

### P1-7 加载失败无常驻错误态、加载中无提示，签到按钮可永久消失

- 位置：`web/src/portal/usePageData.ts:29-32、56-64、71`；`web/src/portal/components/Attendance.vue:16-26、51、62`
- 现象：`fail()` 只弹 6.5 秒 toast；`usePageData` 返回的 `loaded` 在 11 个页面里**一处都没用**，全仓没有 `error` 状态。断网或后端 500 首次进入时 `body` 恒 null，页面渲染成空壳，连"暂无数据"都不出现（空态条件写作 `v-if="data && !rows.length"`）。
- 打卡条更严重：首次请求失败后 `ready` 永远 false，整条 `:hidden`，用户彻底无法打卡且无重试入口；且它不订阅 `store.refreshSeq`，别处刷新后状态仍旧。
- 修复：`usePageData` 增加 `error` ref，`PortalPage` 顶部渲染常驻 `.note.is-error` + 重试按钮；打卡条 `watch(() => store.refreshSeq, refresh)`，失败时保留按钮并支持点击重试。

### P1-8 设备 `host` 无白名单 → 任意内网 TCP 连接与双向读写

- 位置：`app/device_registry.py:66-71`、`app/device_registry.py:162`、`app/main.py:196-207`、`app/main.py:360-369`、`app/transports.py:114-119`
- 现象：`host = dev.get("host")` 只校验"非空字符串"；`mutable` 集合包含 `host`/`dap_port`/`uart_port`，允许 PATCH 修改；连接处 `s.connect((host, dev.get("dap_port", 4441)))`、`TcpStream(host, port)`，`/serial/send` 直接把 `base64.b64decode(body["b64"])` 写出。
- 影响：任何已登录会话（含 emergency）可 `POST /api/v2/devices` 注册 `host=任意内网IP`，再 `/probe` 探测、`/serial/open` + `/serial/send` + `/serial/history` 双向收发——打内网 Redis/Docker API/管理口并拿到回显。这不是理论 SSRF，是带回显的 TCP 代理。
- 修复：`device_registry.py:66` 后按 `ipaddress` + 允许网段（`SCAN_SUBNET`/显式 ALLOWLIST）校验，`update()` 与 `main.py:196` 的 probe 复用同一校验函数。

### P1-9 `revoked_after` 全线失效：改密/禁用/应急轮换都不撤销既有会话，且文案谎报

- 位置：`app/auth/sessions.py:160-169`、`app/auth/accounts.py:198/212`、`app/auth/emergency.py:53/66`、`app/main.py:969/1014/1066`
- 现象：`session_state` 只有 `role == "emergency"` 分支读 `revoked_after` 并比较 `rec["created"] < ra`，**member 分支完全不读**（只看 recheck 宽限期）；`accounts.py:198/212` 写的账号级 `revoked_after` 无任何消费者；`main.py:969/1014` 存进 extra 的是"登录时"的快照值，`created < ra` 恒假，所以应急轮换密码也踢不掉会话；而 `main.py:1066` 仍返回"密码已重设，其他设备上的旧会话已失效"。另外 `sessions.prune()` 全仓库无调用。
- 影响：账号被盗后改密/禁用无效，旧 token 可用到 `SESSION_MEMBER_TTL_SEC`（默认 12h），唯一实际撤销途径是飞书侧离职。
- 修复：`session_state` 前统一查 `accounts.get(open_id)`：`status != "active"` → revoked；`acc["revoked_after"] and rec["created"] < acc["revoked_after"]` → revoked；emergency 同理改读 `emergency.list_users()` 当前值；在 `guard.recheck_loop` 里调用 `sessions.prune()`。

### P1-10 被禁用账号可经飞书 onboarding 自助复活

- 位置：`app/main.py:1022-1037`、`app/auth/accounts.py:165-175`（`"status": "active"` 在 :171）
- 现象：onboard 端点只要求 member 会话 + open_id，随后 `auth_accounts.create(...)`；`create` 重建 dict 时无条件写 `"status": "active"` 并丢掉 `revoked_after`。
- 影响：`accounts.disable` 只挡本地登录；被禁用户仍能飞书登录 → `onboarded=False` → 只放行 onboarding_api → 调 onboard → 状态被写回 active、密码被覆盖。本地"开除/禁用"无效。
- 修复：`accounts.py:164` 前加 `if old.get("status") == "disabled": raise ValueError(...)`；重建时保留 `revoked_after`。

## 4. P2（22 项）

### 安全与部署

1. **`record_id` 未校验直接拼进飞书 URL（路径注入）** — `app/portal/writer.py:100`、`writer.py:116`、`writer.py:132` 均为 `f"/tables/{tid}/records/{record_id}?..."`，`record_id` 来自 API 路径参数，全仓无格式校验（`cache_store._resolve()` 只处理 `loc_` 前缀）。成员账号可构造含 `/`、`..`、`?` 的 id，让门户用应用身份代发任意 Bitable 子路径请求。修复：入口校验 `^rec[A-Za-z0-9]{1,64}$` 或 `loc_` 临时 ID。
2. **systemd 全部以 root 运行** — `deploy/portal.service:13` `User=root`（另 `portal-backup.service:7`、`portal-health.service:7`、`portal-redirect.service:9`），且绑 `0.0.0.0:80`；单元注释写"降权见运维手册"但未落地。建议 `User=portal` + `AmbientCapabilities=CAP_NET_BIND_SERVICE`。

### 并发与正确性

3. **`store.current()` 首读缓存击穿** — `app/portal/store.py:309-341`：先在 `_read_lock` 内查缓存，释放锁后反序列化，最后再取锁写缓存；N 个线程同时命中新版本会各自完整反序列化一遍（5000 条任务约 104 ms/次）。另首次仍调 `get_meta("current_version")`（走写锁 `_lock`）。修复：反序列化也在锁内，或加 single-flight 标记。
4. **工时精度链三处不一致** — `cache_store.py:786` 用 4 位、`cache_store.py:367` 合并用 6 位、`cache_rules.py:151-153` 推送默认 2 位（注释称"与签退口径一致"，实际不一致）。两次 3.3333h：合并得 +6.67、分推得 +6.66，结果取决于时序。建议全链统一 4 位并集中成一个常量。
5. **关联列多值只取第一个且不记 issue** — `app/portal/normalize.py:129-139` 取 `rids[0]`；`app/portal/compute.py:68` 用 `t.get("project_id") == project_id` 计完成率，导致多项目事项在其他项目里漏算（1/2 变 1/1）。另外 record_ids 顺序抖动会让 `project_id` 抖动 → 内容摘要变化 → 每次同步都发新版本。修复：排序后再取，或保留多值列表并在 compute 里用集合判断。
6. **同步 total 对账过脆** — `app/portal/sync.py:251/258-259`：`len(items) != total` 就抛 `parse`，翻页期间一条增删（5000→5001）会让整轮作废，比赛周可连续失败；`d.get("total", total)` 遇 `null` 会静默关掉对账。建议容差（±1）并对 `null` 显式告警。
7. **签退回显用快照** — `app/portal/api.py:2120` `est = round((m.work_hours or 0) + hours, 2)`，连续两次签退时页面工时"回退"（11.03 vs 本地视图 11.55）。与 P1-3 同源。

### 前端交互与对比度

8. **筛选条件不进 URL** — `web/src/portal/store.ts:46-50`，在 `/tasks` 选好筛选后 F5 或分享链接即回默认。修复：变化时 `router.replace` 写 query，初始化从 `route.query` 读回。

10. **甘特条与进度条用品牌黄填充，对比度 1.01–1.27:1** — `web/src/shared/styles/components.css:646-652、496-497`。`#FFFA00` vs `#FFFFFF` = 1.11:1，vs 进度轨道 `#D9D9D9` = 1.27:1（图形要求 ≥3:1），条的宽度（= 工期）几乎不可见。修复：填充改 `--c-ink` 或浅黄 + 深描边。

### 越权边界与输入健壮性

15. **组员白名单只限列、不限归属** — `app/portal/api.py:990-1013`：`_MEMBER_TASK_FIELDS` / `_MEMBER_STATUS_RANGE` 允许组员写提交/验收时间与状态，但不校验事项归属，任意组员可改任意组事项，污染考核。修复：按 `owners`/`owner_group` 做归属校验（需补 `member_groups()`）。
16. **请假设置不限组** — `app/portal/api.py:1900-1913`：`open_id, _ = _require_leader(request)` 丢弃了 `groups`，`:1909` 只 `_resolve_local(rid)` 不比对组别，组长可给任意组成员设/取消请假。修复：比对 `set(m["groups"]) & set(groups)`。
