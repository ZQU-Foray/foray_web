## 1. 已确认的产品需求

| 项目 | 已确认规则 |
| --- | --- |
| 产品定位 | 将现有局域网调试台扩展为战队管理门户，调试台作为独立模块保留 |
| 网络范围 | 所有网页与调试能力均在实验室局域网使用；服务器联网时访问飞书 API |
| 管理数据 | 统一存放在组织的飞书多维表格；当前尚未建立，需要设计并初始化 |
| 编辑边界 | 第一版只读展示；项目、事项、节点和日程仅在飞书中维护 |
| 战队分组 | 机械、硬件、电控、算法、运营 |
| 紧急事项 | P0 最高，依次 P1、P2、P3；另外标记逾期和即将到期 |
| 进度 | 采用事项计数法，不加权；状态为未开始、进行中、受阻、已完成、已取消 |
| 倒计时 | 展示比赛时间、关键检查时间 |
| 日程 | 默认展示战队公共安排；可以进入详情；不按组别限制读取 |
| 登录 | 管理页面通过飞书识别指定组织成员，不开放外部组织访问 |
| 调试权限 | 暂不区分组织成员的调试角色；实验室断网时调试功能必须正常 |
| 刷新 | 后端每 60 秒同步；页面自动更新；支持手动刷新；失败时保留缓存并标明更新时间 |
| 视觉 | 沿用现有调试台的浅色、酸性黄工业风，扩展统一的管理界面 |

### 1.1 已确认的访问决策 D1

**调试台平时要求登录，另外提供本地应急登录，保证断网后新浏览器及服务重启后仍可调试。**

- 飞书有效组织成员可使用管理页面和全部现有调试功能，不区分调试角色。
- 本地应急身份仅授予调试能力，不可查看管理数据、调用管理 API 或冒充飞书成员。
- 应急入口由用户主动选择并输入本地凭据，不因飞书超时自动放行，也不要求先通过飞书失败检测才能出现。
- 应急凭据由服务器维护者在本地创建、轮换和撤销；不要通过飞书或外部网络完成应急校验。
- 默认应急会话绝对有效期 8 小时；凭据轮换可撤销旧会话。此为可配置实施默认值。
- 应急登录入口可以在联网时存在，依然要求独立凭据；不把不可靠的“断网检测”当安全边界。

### 1.2 本文采用的实施默认值

以下是可调整的设计默认值，不是用户额外提出的需求：

- 一个事项只有一个主责组，可有多个协作组、多个负责人；统计归属以主责组为准，避免重复计数。
- “即将到期”默认为剩余 72 小时内；未完成且已超过截止时间为逾期。
- 管理页面查看数据不按组别鉴权；分组只用于筛选与统计。所有选入数据源的内容都视为向全体有效组织成员公开。
- 第一版不做“我的事项”专页，不做个人日历接入；保留人员标识，为后续扩展准备。
- 数据源配置先使用服务器配置文件与环境变量，不额外开发网页管理员后台。
- 名称暂为“Foray 战队管理门户”；遵循当前项目名称，正式上线前可修改。

### 3.1 导航结构

| 页面 | 内容与行为 |
| --- | --- |
| `/login` | 飞书登录、登录异常说明；显示符合 D1 的调试入口 |
| `/` | 战队总览：倒计时、五组紧急事项、近期公共日程、项目摘要、同步状态（**2026-09-12 实际落地版：项目摘要移除、新增打卡工时排行，见 `portal-progress.md` v2.3**） |
| `/projects` | 项目筛选、列表、进度、事项统计；进入项目详情 |

| `/tasks` | 五组与全部视图；按 P 等级、状态、负责人、项目筛选；事项详情 |
| `/schedule` | 默认近期公共安排，支持日历或列表切换；点击日程查看时间、地点、说明 |

所有管理详情都进行组织成员认证，但不实施组别限制。“不鉴权组别”不等于“不需要登录”。

### 3.2 首页布局

1. 顶部导航：战队名称、主要页面入口、用户身份/退出、调试台入口。
2. 重要节点：按未来时间升序展示最多 3 个比赛或检查倒计时，可查看全部。
3. 五组紧急事项：各展示最多 5 条未完成事项，明确 P 标签、负责人、截止时间和逾期状态。
4. 近期日程：默认未来 7 天，显示正在进行的活动，允许展开详情。
5. 项目摘要：每个项目显示完成率、完成/有效事项数、受阻数和逾期数。
6. 同步状态：最近成功同步时间、刷新按钮、失败或陈旧提示。

布局从桌面管理阅读出发，兼顾 480px 窄屏；甘特图可在自身区域横向滚动，不让整页溢出。

### 3.3 视觉与交互约束

复用当前 `style.css` 的纸白、墨黑、酸性黄、网格纹理和字体回退；提取共享样式时避免改变调试控件语义。装饰不遮挡内容，P 等级与状态同时提供文字，不能只靠颜色。

管理数据刷新只更新内容，不触发整个页面重载、不重置筛选、不打断详情阅读。详情支持可复制链接与浏览器返回。仅在调试页面加载调试脚本和建立硬件连接，门户首页不得默认打开串口或发射会话。

### 4.5 飞书端建议视图与初始化

- 事项：全部、按主责组、P 等级排序、未完成、甘特视图。
- 项目：进行中项目；节点：未来节点；日程：公共日历视图。
- 视图用于飞书内维护。网页读取底层记录并自行计算、筛选和绘制，不承诺一比一复制飞书甘特 UI 或全部视图配置。
- 提供字段清单、枚举字典和匿名示例；先建立项目表，再配置关联字段，记录真实表/字段 ID。
- 飞书登录权限不等于 Base 读取权限。应用需拥有适当 API 权限及该 Base 的资源访问权限。
- 实施阶段提供人工配置说明；没有另行授权时，不自动在组织飞书中创建或修改数据。

## 5. 统一计算口径

### 5.1 进度与统计

`有效事项数 = 关联到该项目且状态不是已取消的事项数`。

`完成率 = 已完成事项数 / 有效事项数 × 100%`，展示四舍五入到整数，并展示分子、分母。无有效事项时显示“暂无事项 / —”，不显示 100%。受阻属于未完成且计入分母。

主责组统计每条事项只计一次；协作组用于筛选和详情展示。归档项目默认隐藏，但可筛选查看。被删除项目的残留关联显示“项目已移除”，不让整页崩溃。

### 5.2 紧急事项与日期

- 未完成状态：未开始、进行中、受阻；已完成与已取消不进入紧急列表。
- 排序：P0→P3；同等级逾期优先，再按截止时间升序，缺失截止时间排最后，最终按稳定记录 ID 排序。
- 逾期：未完成且当前时间超过截止边界。即将到期：未完成、未逾期且距离截止边界不超过 72 小时。
- 纯日期截止按 `Asia/Shanghai` 当日结束计算，以次日 00:00 为排他边界；精确时刻按真实时间比较。
- 全部时间入库保留精度和原始值；精确时刻可规范为 UTC，展示统一上海时区。不得把纯日期按 UTC 零点简单转换。
- 日期缺失显示“未设置”；结束早于开始、未知 P/状态列为数据质量异常，不能静默当作正常事项参与进度。展示异常数与排除统计说明。

### 5.3 甘特与倒计时

甘特图按项目和事项的起止日期绘制，颜色体现状态、标签体现 P 等级；缺失日期的事项保留在“未排期”列表，不伪造排期。第一版不支持拖拽修改、不要求依赖线或关键路径算法。

倒计时每秒或每分钟在浏览器本地计算，不因倒计时刷新调用飞书；通过后端 `server_time` 修正明显的客户端时钟偏差。只知道日期时展示天数/今天，不虚构小时级精度。

## 6. 技术方案

### 6.1 总体结构

```text
局域网浏览器
  ├─ 管理页面 ── 本地登录会话 ── 门户 API ── 本地 SQLite 数据快照
  │                                         ↑
  │                                 后台同步任务（60 秒）
  │                                         ↑
  │                                    飞书多维表格
  └─ 调试页面 ── 原调试 REST / WebSocket ── 设备会话 / USB / TCP

飞书 OAuth 建立正常成员身份，可访问管理与调试；本地应急身份只可调试。
```

保留 FastAPI 和原生前端，采用独立页面入口与共享导航/样式。第一版无需引入 React/Vue、Redis、Celery 或微服务；若实施中证据表明需要调整，先在架构记录说明原因和迁移代价。

> 2026-10-20 更新：前端已按此条迁移到 Vue 3（原因与代价、回退方式见 `docs/frontend-vue.md`）；后端仍为 FastAPI 单进程，未引入 Redis / Celery / 微服务。

### 6.2 建议目录（新增部分）

```text
app/
  auth/             # 飞书 OAuth、本地用户会话、成员复核
  feishu/           # 服务端客户端、凭据缓存、字段映射、分页同步
  portal/           # 管理 API、计算与数据规范化

static/
  portal/           # 管理页面脚本与局部样式
  shared/           # 共享导航与设计变量
config/
  feishu.example.json  # 无真实密钥的映射样例
docs/
  team-portal-migration-plan.md
  portal-progress.md
  portal-baseline.md
  feishu-setup.md
  portal-operations.md
```

具体文件名可按现状微调。不要为满足目录树大规模搬迁调试模块。

### 6.3 API 边界

| 新接口建议 | 行为 |
| --- | --- |
| `GET /auth/feishu/start` | 发起 OAuth，绑定随机 state 与浏览器登录事务 |
| `GET /auth/feishu/callback` | 后端交换授权码，验证组织身份，建立本地会话 |
| `GET /api/auth/me` | 当前登录状态和基础用户信息 |
| `POST /api/auth/logout` | 撤销本地会话 |
| `POST /api/auth/emergency/login` | 验证本地应急凭据，建立仅调试会话；限频且不依赖飞书 |
| `GET /api/portal/overview` | 倒计时、组别紧急事项、近期日程、打卡工时排行（**2026-09-12 起不再返回 `projects`**） |
| `GET /api/portal/projects`、`/{id}` | 项目列表和详情 |
| `GET /api/portal/tasks`、`/{id}` | 事项列表和详情 |
| `GET /api/portal/milestones` | 重要节点 |
| `GET /api/portal/schedule`、`/{id}` | 公共日程及详情 |
| `GET /api/portal/sync-status` | 快照版本、成功时间、状态、脱敏错误 |
| `POST /api/portal/sync` | 请求一次合并后的同步任务；不写入飞书业务数据 |

管理 API 都在服务端认证，详情也不能绕过。列表提供过滤、分页和稳定排序；客户端传入的排序字段必须白名单校验。变更本地状态的接口校验 CSRF/Origin。

所有管理数据响应附 `snapshot_version`、`last_success_at`、`server_time` 和 `stale`。无首次快照是“尚无可用同步数据”，不伪装为战队没有事项。

### 6.4 同步与缓存

1. 服务启动先恢复持久快照，后台启动同步；等待飞书不能阻塞 Web 服务或设备初始化。
2. 使用应用身份读取专门配置的组织 Base，不使用当前网页用户的令牌替全站同步。
3. 每 60 秒触发一次四表完整读取；实现所有分页、响应业务错误检查、超时、有限重试、退避与限流处理。数据规模增大后再考虑增量同步。
4. 单一同步锁，定时和手动任务合并；每用户手动刷新建议至少间隔 10 秒，不能按浏览器人数复制飞书请求。
5. 先写候选快照，四表全部成功后原子切换版本，避免显示不一致的跨表数据。失败保留上一完整快照，不删除缓存。
6. 全量成功时识别源记录删除；单条非法数据进入质量报告，关联与统计说明保持可追踪；必要字段缺失/权限失败等结构问题使本次快照失败。
7. 记录 `last_attempt_at`、`last_success_at`、耗时、记录数和错误类别。连续 180 秒未成功默认标记陈旧；失败立即显示失败状态。
8. 页面可每 15 秒检查本地快照版本，变化后更新可见数据；因此健康网络下展示延迟预算约为 60 秒同步周期 + 本轮同步耗时 + 最多 15 秒页面轮询，不宣称严格实时。
9. 飞书访问令牌仅存后端，按接口返回过期信息提前更新，避免刷新并发；日志不记录密钥、令牌或授权码。
10. 网络 I/O 使用异步客户端；SQLite 较重事务放到受控线程执行，不阻塞调试 WebSocket。同步任务使用有界超时并支持服务退出取消。

### 6.5 登录、组织校验与局域网地址

- 创建目标组织的企业自建应用，应用可用范围覆盖战队成员，按实际文档申请最小权限并发布。
- 后端用授权码获取用户身份，验证 `tenant_key` 等可信组织标识与配置一致；以稳定飞书用户标识建立本地用户映射，不使用姓名或邮箱域名认定组织成员。
- 登录会话使用服务端随机会话 ID，Cookie 使用 HttpOnly、适当 SameSite 和 HTTPS 下的 Secure；建议绝对有效期 12 小时，不保存令牌到 localStorage。
- 组织移除后的撤权不是 OAuth 自动完成的工作：阶段 1 验证成员状态读取或成员变更事件能力，阶段 3 选定并实现可测试的复核方案。建议在线最长 5 分钟复核一次；对 API 权限、身份映射与数据范围进行实证核查。
- 飞书成员会话访问管理和调试时使用最近有效成员复核结果；默认复核超过 5 分钟仍失败则暂停该身份的受保护请求，返回“暂时无法确认成员身份”，不能假冒“已退出组织”。用户可主动使用独立应急登录继续调试，不能自动降级为应急身份。
- 用户已退出组织或会话已撤销时，拒绝后续管理 API；页面清除已展示状态。已经被用户看到的数据无法远程收回。
- 确定一个客户端可达的固定局域网主机名及回调路径，建议用可信本地 HTTPS；不要假定任意私网 IP/HTTP 回调都被飞书接受，阶段 1 必须实测当前平台规则与浏览器跳转。
- OAuth 回调是浏览器访问本地服务器，通常不要求飞书服务器主动进入实验室网络；若采用事件 Webhook 则有独立网络可达性要求，不能照搬。第一版不以公网入站作为前提。
- 浏览器和服务器在登录时需要连接飞书；仅有局域网不能完成新的飞书授权。不得把 API 超时当作身份验证成功。

### 6.6 调试离线能力

- D1 同时应用于调试页面、旧/新 REST、旧/新 WebSocket 和 CLI；不能只隐藏按钮。
- 调试所有脚本、样式和必要资源均由本地提供，不依赖 CDN、远程字体或飞书 SDK 下载。
- 飞书凭据未配置、DNS 失败、飞书超时、SQLite 管理快照为空或同步失败时，硬件模块仍应启动。
- 应急身份仅可访问调试模块，凭据使用成熟的密码散列实现并加盐存储，限制失败尝试、支持本地撤销；不能读取缓存管理数据。禁止默认密码和明文配置密码。
- 本地登录会话持久化；服务重启可以继续验证未过期会话。应急凭据存储与管理快照解耦，飞书初始化失败不影响应急验证。
- 管理快照和凭据不放到公开静态目录；结合监听/防火墙和实际实验室网段限定访问，不仅信任任意代理头。
- CLI 增加显式登录/会话文件支持，使用相同服务端认证策略；凭据不放命令行参数，提示交互输入或使用受保护会话文件。不保留绕过认证的旧路由。
- 本地应急管理员操作不等于远程 Web 管理接口；第一版以服务器本地命令创建/轮换账号即可。
- 保留硬件互斥和忙状态；多人均有调试权限不意味着可同时控制同一设备。第一版不扩展为复杂预约系统。
