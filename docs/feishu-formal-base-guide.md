## 3. 事项组织与工作流

业务浏览层次：赛季 → 主责组别 → 机器人 → 子系统 → 工作事项。

机器人表按“赛季＋兵种”维护唯一实体；子系统表是共享分类，允许维护者按实际情况扩展。技术事项关联机器人和子系统；运营事项可以没有这两项。

每条事项只有一个主责组和一位主要负责人，可以有多个协作组和协作人。跨组且具有独立交付物的工作拆分为多条事项，通过“相关事项”连接；先后依赖填“前置事项”。

1. 组长提出事项，管理员确认后录入赛季、主责组别、P级别、负责人、验收组长、计划起止、交付物和验收标准。
2. 负责人反馈执行状态、完成度、当前进展、阻塞原因和交付附件，由管理员更新。
3. 达到交付要求后，管理员根据负责人的提交将事项设为“待验收”，记录提交时间。
4. 组长进行实际业务验收，管理员依据结论录入验收结果、意见和时间。“通过”才会使最终状态变为“已完成”。
5. 退回时由管理员将执行状态调整为“进行中”或“受阻”，说明待修改项；取消需记录原因。

创建人、更新人字段反映实际录入者，通常是管理员，不能当作业务负责人或实际验收人。负责人和验收组长字段记录真实业务身份；未知人员保持空白。

“最终状态”是公式字段。“执行状态”不提供已完成选项。公式优先处理验收通过和取消，其余显示执行状态，空执行状态按未开始显示。完成度使用0至100的数字约定，不能代替验收结论。

| 优先级 | 判定建议 |
| --- | --- |
| P0 | 涉及安全、关键比赛或联调，必须立即组织处置 |
| P1 | 阻塞重要目标或关键依赖，优先安排 |
| P2 | 正常计划内工作 |
| P3 | 优化、储备和低紧迫事项 |

相同优先级按截止时间从早到晚处理，逾期与受阻单独关注。具体响应时限由战队确定，不预设虚构的硬性截止。

## 4. 测试、问题和故障

测试人员提供环境与版本、步骤、预期结果、实际结果和附件，由管理员为每次测试新增独立记录。失败时管理员建立问题或故障并关联“发现测试”，需要实施改动的另建修复事项并关联。

“问题”表示缺陷或风险，“故障”表示已经发生的功能失效。负责人提供根因、方案和修复版本，管理员更新处理状态。复测由管理员新增测试记录，保留原失败证据。组长确认复测结论后，管理员将关闭结论设为“通过”，最终状态才显示“已关闭”。

## 5. 节点、日程与视图

重要节点的目标时间为倒计时源数据，类型区分比赛、关键检查与内部里程碑，通过“展示倒计时”选择门户展示。时间不确定时留空；不能用假日期填满界面。公共日程维护开始与结束、组织者、参与人员、涉及组别、地点和完整安排；组织成员跨组可读。

工作事项提供五组视图、P0至P3未完成视图、待验收、受阻事项、未分配负责人、项目甘特和进度看板。测试提供失败测试，问题与故障提供未关闭、故障记录和待验收，节点提供比赛与关键检查，日程提供待进行。

API对公式字段的视图筛选不支持，因此未完成与待验收视图使用“执行状态＋验收结论”组合过滤，问题表同理。视图筛选不是权限控制。

- 项目甘特：已将错误的默认日期绑定改为“计划开始→计划截止”，标题为“事项名称”，重新打开后确认配置已保存。
- 进度看板：已改为按“执行状态”分组并点击保存。完成与否仍以验收结论及最终状态为准。
- 公共日历：已通过界面创建，视图ID为`vew6U1wJao`，日期绑定为“开始时间→结束时间”，标题为“日程名称”。API列出视图时返回view_type=unknown，应保留该真实返回值，另记录UI类型为calendar，不把它误当成无效视图。

## 6. 当前权限与未来扩展

已应用：高级权限v2；默认“普通用户”和“成员 · 待启用（只读）”对全部数据表只读；现有测试Base唯一用户管理员可管理正式Base。新成员角色未绑定人员，不能作为正式执行角色使用。

**当前只允许管理员维护，不启用以下精细角色。** [feishu-formal-base-roles.json](feishu-formal-base-roles.json)保留未来可选规则，采用base/v2字段权限语义：1可阅读、2仅新增时填写、3可编辑。未经用户再次选择自主编辑方案，不应用这些规则；不要把它们交给旧版bitable/v1接口，其字段权限数值不同。

| 角色 | 未来自主编辑模式的计划权限 |
| --- | --- |
| 普通用户 | 全部表可读 |
| 成员 · 本人执行与测试 | 不可创建官方工作事项；只可更新本人负责且尚未通过/取消事项的执行字段；可记录测试与问题，不能验收关闭 |
| 五个组长角色 | 创建、分派和验收主责组内事项及问题；跨组只读；维护本人组织或创建的节点、日程 |
| 文档管理员 | 基础字典、人员、结构、权限与归档管理 |

待实施配置的目标是：禁止普通成员编辑任务负责人、优先级、主责组别和验收字段，禁止删除记录及修改选项配置，已通过或取消事项不再允许普通成员更新。当前实际状态是整体只读，上述精细编辑规则尚未生效。读取权限对各组开放，不以组别限制详情查看。

### 6.1 应用权限

以下应用身份权限已由用户开通，并完成读取/更新调用验证：

- `base:role:read`：读取新版高级权限角色。
- `base:role:create`：创建业务角色。
- `base:role:update`：更新默认角色和业务角色。
- `docs:permission.setting:read`：已成功读取公开分享和链接访问设置。

API创建及更新自定义业务角色返回1254304：Only Available For Business and Enterprise Editions。界面可以创建角色，但选择“与成员本人相关的记录”时弹出“请升级套餐版本以使用行列权限”。已撤销尝试中的编辑权限，将占位成员角色保存为全部只读，API回读确认两类角色均为11表只读。未点击升级、联系客服或启动付费操作。用户已选择管理员集中维护，这一套餐限制不再阻塞当前模式；未来若开放成员自主编辑，再重新评估。

分享范围已通过飞书界面收紧，并通过API回读确认：external_access=false、invite_external=false、share_entity=only_full_access、link_share_entity=tenant_readable。即禁止组织外分享，仅管理员可以管理协作者，组织内获得链接者仍可阅读。此前API写入缺少docs:permission.setting:write_only的问题已通过授权的界面操作解决；仅为本次已完成操作无需再补开该权限。

不必为此直接开通全部通讯录或云盘权限。人员身份确认后再按需要使用角色成员接口，或者由管理员在飞书界面绑定成员。

### 6.2 当前模式的运行规则

- 只有已确认的文档管理员录入和修改工作信息；不因为人员表写了“组长”就授予文档编辑权限。
- 其他成员通过组织内链接只读浏览；管理员负责收集各组反馈并更新。
- 未对未知人员授予权限，未批量绑定角色，未对外分享。
- 新增管理员由现有管理员明确指定；不把“编辑者”系统角色分配给普通成员，否则会突破只读约定。
- 已验证保存的角色和分享设置；未使用独立普通成员账号进行访问会话测试。正式邀请成员后应补做一次只读访问验证。

### 6.3 未来自主编辑模式的验收清单

仅在用户以后明确选择自主编辑且套餐支持行列权限后执行。填写“成员与职责”不等于自动绑定高级权限，届时先确认名单、落实规则，再用普通成员及组长账户实测：

1. 普通成员可以查看其他组事项和公共日程详情。
2. 普通成员不能创建官方工作事项、修改他人事项、改主责/优先级/负责人或直接验收通过。
3. 本人可更新未完成事项，提交待验收；组长通过后，本人不可继续修改执行资料。
4. 组长可以创建和验收本组事项，跨组编辑被拒绝；检查新增记录时主责组别的约束。
5. 普通成员新建测试/问题时，新增字段填写权限与后续编辑权限符合规则；确认负责人本人条件与创建人本人条件行为。
6. 不授予覆盖这些规则的额外“可管理”或宽泛编辑角色；检查多角色权限叠加。
7. 确认外部、匿名、组织链接访问范围及角色默认值，按战队实际成员范围开放。

上述检查尚未通过成员会话实测，不应宣称权限完全验收。当前不自动向全组织授予编辑权限，也未按未知名单绑定组长。

## 7. 数据约束边界

基础字段和关联已建立，但“每赛季每兵种一台”、必填项、机器人与事项赛季一致、开始不晚于截止、进度0至100，尚未由跨表规则或自动化强制保证。初始数据遵守这些规则，后续由维护者检查；需要强制化时，再单独配置支持的飞书表单/自动化或服务器校验。

飞书公式存在异步计算延迟。网页同步应允许短时公式缺值，保留上次有效快照，并且可根据原始执行状态与验收结论计算展示状态。应用管理员令牌能够绕过普通成员角色限制，因此应用身份测试只能证明计算与结构，不能证明普通成员授权安全。
